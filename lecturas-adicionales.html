    14. Lecturas adicionales

    Este documento presentó el lenguaje Kotlin y las bibliotecas más utilizadas para escribir aplicaciones por capas, clientes y servidores de red, y servicios web en la máquina virtual de Java. Estos son los principales temas que continúan a partir de aquí.

    14.1. Procesamiento de documentos XML

    JSON ha reemplazado en gran medida a XML para el intercambio de datos, pero XML sigue en uso (archivos de configuración, formatos de documentos, servicios SOAP existentes). Kotlin usa directamente la API XML del JDK, dentro del paquete [javax.xml]:

    • DOM ([DocumentBuilder], [Document], [Element]): el documento se carga en memoria como un árbol, que luego se recorre y se modifica;
    • StAX ([XMLStreamReader], [XMLStreamWriter]): el documento se lee o se escribe sobre la marcha, sin cargarlo por completo en memoria;
    • XPath ([javax.xml.xpath]) para consultar un documento y XSLT ([javax.xml.transform]) para transformarlo.

    Además del JDK, Jackson puede leer y escribir XML mediante su módulo [jackson-dataformat-xml], tal como lo hace con JSON (capítulo 5), y la biblioteca kotlinx.serialization de JetBrains, que genera el código de serialización en tiempo de compilación, también admite formatos XML desarrollados por la comunidad.

    14.2. Aplicaciones web

    El capítulo 13 cubre únicamente los servicios web (aplicaciones que producen datos). Para aplicaciones web que generan páginas HTML, o para otras formas de escribir servicios web en Kotlin, se dispone de lo siguiente:

    • Spring MVC con un motor de plantillas como Thymeleaf: páginas generadas en el servidor. Spring admite Kotlin igual que Java (clases de datos, corrutinas en los controladores, Kotlin para la configuración de rutas); el autor escribió el curso “Introducción paso a paso al framework web Spring” (septiembre de 2026);
    • Ktor, el framework web de JetBrains, escrito en y para Kotlin: servidores y clientes HTTP construidos sobre las corrutinas del capítulo 9, configurados mediante código Kotlin en lugar de anotaciones;
    • otros frameworks de la JVM que admiten Kotlin: Quarkus, Micronaut, Javalin y los servidores de aplicaciones Jakarta EE;
    • interfaces escritas en JavaScript (Vue.js, Angular, React) que consumen servicios web Kotlin; el autor escribió el curso “Introducción paso a paso al framework Vue.js” (septiembre de 2026). El propio Kotlin puede compilarse a JavaScript (Kotlin/JS) o a WebAssembly (Kotlin/Wasm), lo que también permite escribir el lado del cliente en Kotlin.

    14.3. Aplicaciones móviles y de escritorio

    Este documento no cubre las interfaces gráficas de usuario: hoy en día, las aplicaciones de gestión se construyen con mayor frecuencia con interfaces web. Sin embargo, es un ámbito en el que Kotlin se usa ampliamente:

    • en Android, Kotlin es el lenguaje recomendado por Google, y la interfaz de usuario se construye con Jetpack Compose, una biblioteca declarativa escrita íntegramente en Kotlin; las corrutinas (capítulo 9) se usan para mantener la interfaz receptiva durante el acceso a la red o a bases de datos;
    • Compose Multiplatform, de JetBrains, extiende Compose para escribir interfaces de escritorio (Windows, Linux, macOS), iOS y web con el mismo código;
    • De manera más general, Kotlin Multiplatform permite compartir código de lógica de negocio (las capas [business] y [dao] del capítulo 6, por ejemplo) entre la JVM, Android, iOS (mediante Kotlin/Native, que genera código máquina sin máquina virtual) y la web;
    • en la JVM, las bibliotecas Java Swing y JavaFX siguen siendo utilizables desde Kotlin. Los conceptos tratados en los Capítulos 7 (escuchas de eventos) y 9 (regreso al hilo de la GUI con [Dispatchers.Main]) se aplican directamente aquí.

    14.4. Pruebas

    El Capítulo 6 presenta JUnit y [kotlin.test]. A menudo se complementan con:

    • Kotest, un framework de pruebas escrito para Kotlin, que ofrece varios estilos para escribir pruebas y una amplia biblioteca de aserciones ([list shouldHaveSize 7]);
    • MockK, la biblioteca de “mocks” (objetos simulados) para las capas de las que depende la capa bajo prueba, diseñada para Kotlin (clases finales, objetos, funciones de suspensión); Mockito sigue siendo utilizable;
    • kotlinx-coroutines-test, que ejecuta pruebas de código basado en corrutinas usando un reloj virtual: un [delay(10_000)] se ejecuta al instante;
    • Testcontainers, que lanza una base de datos real (MySQL, PostgreSQL…) en un contenedor Docker durante las pruebas de integración;
    • las herramientas de prueba de Spring Boot ([@SpringBootTest], [MockMvc]) para probar un servicio web sin desplegarlo.

    14.5. Rendimiento

    Un programa Kotlin es ejecutado por la máquina virtual Java (JVM): se beneficia de la compilación just-in-time y de las optimizaciones en tiempo de ejecución, con un rendimiento equivalente al de un programa Java. Entre las herramientas que van un paso más allá:

    • la herramienta JMH (“Java Microbenchmark Harness”), que se puede usar directamente en Kotlin o mediante el complemento de Gradle kotlinx-benchmark, para medir con precisión el rendimiento del código teniendo en cuenta el calentamiento de la máquina virtual;
    • JDK Flight Recorder y JDK Mission Control, que registran y analizan el comportamiento de un programa en producción; IntelliJ IDEA incluye un generador de perfiles y un depurador de corrutinas;
    • la compilación anticipada a código nativo con GraalVM Native Image: un ejecutable independiente que se inicia en unos pocos milisegundos, a costa de restricciones en la reflexión; Spring Boot y Quarkus pueden generar estos ejecutables a partir de código Kotlin;
    • la elección del recolector de basura (G1 por defecto, ZGC para pausas muy cortas con grandes montones de memoria).

    14.6. Despliegue

    Un programa Kotlin se despliega igual que un programa Java: como un archivo [.jar] ejecutado por un JDK instalado en la máquina ([java -jar application.jar]), siempre que se incluya la biblioteca estándar de Kotlin (es lo que hacen los scripts generados por [gradlew installDist], Capítulo 2; Spring Boot genera un [.jar] independiente que contiene todas sus bibliotecas), como una aplicación independiente que incorpora una máquina virtual reducida a lo estrictamente necesario (herramientas [jlink] y [jpackage] del JDK), o en un contenedor Docker (Spring Boot genera directamente una imagen de contenedor mediante [gradlew bootBuildImage]).

    14.7. Recursos

    • el sitio web oficial de Kotlin, con su documentación, tutoriales y páginas “What’s New” de cada versión: https://kotlinlang.org;
    • el entorno de pruebas en línea Kotlin Playground, para probar código Kotlin en un navegador;
    • los ejercicios Kotlin Koans , disponibles en el sitio web de Kotlin y en IntelliJ IDEA;
    • las propuestas de evolución del lenguaje (KEEP), para mantenerse al día con las novedades de las próximas versiones: https://github.com/Kotlin/KEEP;
    • el código fuente del compilador y de la biblioteca estándar, disponible en GitHub: https://github.com/JetBrains/kotlin, y el código fuente de las corrutinas: https://github.com/Kotlin/kotlinx.coroutines;
    • la documentación de la API de Java SE 25, para las clases del JDK utilizadas desde Kotlin: https://docs.oracle.com/en/java/javase/25/docs/api/;
    • los libros *Kotlin in Action* (Manning) y *Effective Kotlin* de Marcin Moskała y, para la concurrencia en la JVM, *Java Concurrency in Practice* de Brian Goetz et al. (Addison-Wesley).
